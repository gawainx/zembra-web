# r031-inline-tag-positions 需求澄清

日期：2026-08-25

## 需求背景

用户可以在正文任意位置使用 tag。当前卡片展示态会移除正文中的 `#tag` marker，再将所有 tag 集中显示在正文前；编辑态和展示态因此位置不一致，也不符合 Logseq 式的行内阅读体验。

## 已确认决策

```text
原文：通过和 AI 对话，能够在 #Cancro 方面得到帮助
展示：通过和 AI 对话，能够在 [#Cancro] 方面得到帮助
```

| 决策项 | 结论 |
| --- | --- |
| 渲染位置 | 编辑态与卡片展示态均按原始 Markdown 中 `#tag` 的位置渲染。 |
| 行内行为 | chip 随文本流动，不固定在行首；宽度不足时在 chip 前后正常换行。 |
| chip 行为 | 单个 tag chip 内不换行，保留完整 path 文本。 |
| 卡片 metadata | 不再将 tag 集中渲染在正文首行。 |
| 数据契约 | 原始 Markdown、tag 解析、筛选和保存 payload 保持不变。 |

## 兼容代价评估

保留“卡片首行 metadata tag”与“正文内联 tag”两条展示路径会造成重复标签、位置歧义和额外测试负担。本需求采用正向修改：卡片仅从正文原始位置渲染 tag chip。

## 验收标准

| 场景 | 期望 |
| --- | --- |
| 正文句中包含 `#tag` | tag 替换为行内 chip，前后文字位置与顺序不变。 |
| 正文包含多个 tag | 每个 tag 在自己的原始位置渲染，不集中到段首。 |
| 窄宽度 | chip 自身不折断，文本可在 chip 前后自然续行。 |
| 编辑与保存后展示 | tag 位置和对应的 Markdown 字符串一致。 |

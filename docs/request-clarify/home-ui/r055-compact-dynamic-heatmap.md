# r055-compact-dynamic-heatmap 需求澄清

日期：2026-08-29

## 已确认目标

首页侧栏的活跃热力图不再以固定天数决定数据范围。展示多少个日期由热力图实际格数决定，数据层接收该格数作为显式参数并返回对应数量的连续自然日统计。热力图不显示格内日期数字、星期标签或首末日期标签，只保留按时间排列的热力方块；每天的日期与笔记数继续通过无障碍名称和悬停提示提供。方块及间距缩小为接近 GitHub contribution graph 的紧凑密度。

## 数据范围

本次只覆盖 Supabase 模式。Supabase 数据源直接读取 workspace 的全部可见笔记，由调用方传入热力图格数生成对应数量的真实连续统计。`NotesClient`、store 加载方法与 Supabase 聚合函数均接收这个显式参数，不保留固定 30 天或其它默认天数。Backend 模式和 `GET /notes/stats/daily-counts` 不在本次需求范围内。

## 布局规则

热力图按 GitHub 的周列方式排列，每列 7 个星期位。列数由渲染后的侧栏可用宽度，以及 `--heatmap-cell-size`、`--heatmap-cell-gap` 两个主题 token 实时计算；格数等于列数乘以 7，并传入统计接口。默认 token 为 16px 方块、4px 间距和最多 1px 的方块圆角，300px 侧栏通常显示 15 列、105 天；宽度变化时自动重算，不保留固定周数或天数。

# r039-sanitize-rich-text-paste 需求澄清

日期：2026-08-27

## 需求背景

编辑框实时渲染 Markdown 和列表的体验需要保留。当前问题只发生在从网页或文档复制富文本时：Tiptap 会把来源的 HTML 样式转换为编辑器 mark，例如下划线会持续显示，用户难以回到普通文本。

## 已确认决策

| 决策项 | 结论 |
| --- | --- |
| 编辑器形态 | 保留当前 Tiptap 实时 Markdown 渲染、列表和工具栏。 |
| 粘贴行为 | 外部剪贴板内容一律读取 `text/plain` 并按无样式文本插入。 |
| 格式边界 | 外部富文本的下划线、颜色、字号、粗体等样式不进入编辑器。 |
| 用户 Markdown | 用户主动输入的 Markdown 继续按当前规则实时渲染。 |
| 数据契约 | 草稿、提交 payload 与既有解析、渲染逻辑不变。 |

## 兼容代价评估

保留外部富文本并把其样式转换为 Markdown，需要逐一规定哪些 HTML 样式保留、如何映射和何时退出，粘贴行为会持续存在歧义并增加测试与维护成本。本需求采用正向的纯文本粘贴路径，不维护双轨转换逻辑。

## 范围边界

| 类型 | 内容 |
| --- | --- |
| In Scope | 在 Tiptap 的粘贴入口拦截外部富文本，只插入剪贴板纯文本。 |
| In Scope | 覆盖创建和卡片编辑共用编辑器的粘贴行为。 |
| Out of Scope | 改动实时 Markdown、列表、tag 候选、工具栏或笔记卡片渲染。 |
| Out of Scope | 富文本到 Markdown 的转换或保留来源样式。 |

## 验收标准

| 场景 | 期望 |
| --- | --- |
| 粘贴带下划线文本 | 插入普通文本，未形成下划线 mark。 |
| 粘贴带颜色、字号或粗体文本 | 只插入文字，不保留来源视觉样式。 |
| 手动输入 `**重点**` | 仍按当前方式实时显示粗体。 |
| 输入或粘贴 Markdown 列表文本 | 现有列表编辑和提交行为不变。 |

# R047 生产包拆分性能改造需求澄清

日期：2026-08-27

## 需求理解

用户要求完成生产构建性能改造，解决 Vite 在压缩后报告超过 500 kB 的 JavaScript chunk 警告，避免首屏把不需要的第三方依赖和业务模块整体装入主包。

本轮以 `npm run build` 的生产产物为验收依据。现有基线只有 `index`、`LiveMarkdownEditor` 和样式三个产物，其中 `index` 约 783 kB、`LiveMarkdownEditor` 约 536 kB，两个 JavaScript chunk 都超过 Vite 默认阈值。

## 已确认决策

| 问题 | 决策 |
| --- | --- |
| 改造目标 | 让生产构建不再输出超过 500 kB 的 chunk 警告，并降低首页初始 JavaScript 负载 |
| 拆分方式 | 复用 Vite 的 Rollup 配置，以依赖用途配置稳定的 `manualChunks`，不引入新的分析或运行时依赖 |
| 编辑器 | 保留既有的懒加载入口；继续将 Tiptap 与 ProseMirror 相关模块延后到编辑器实际渲染时下载 |
| 第三方依赖 | 将首屏共享框架依赖和按需功能依赖拆为独立缓存 chunk，避免主包混装 |
| 用户行为 | 不改变路由、编辑、同步、认证或笔记业务行为 |

## 范围确认

### In Scope

| 范围项 | 说明 |
| --- | --- |
| Vite 构建输出策略 | 为 React、路由、i18n、Supabase、图标和编辑器依赖设置按用途拆分规则 |
| 编辑器依赖隔离 | 细分当前大于阈值的编辑器 chunk，使其保持延迟加载且不产生超阈值产物 |
| 构建验证 | 对比改造前后产物清单和 gzip 大小，确认构建无 chunk-size 警告 |
| 回归验证 | 运行现有前端测试和生产构建 |

### Out of Scope

| 非范围项 | 原因 |
| --- | --- |
| 更换或移除 Tiptap 功能 | 本轮只调整产物边界，不改变编辑器能力 |
| 新增构建分析依赖 | 现有 Vite 产物报告足以验证本需求 |
| 重写页面或状态架构 | 不属于解决 bundling 边界的必要改动 |
| 服务端 API、数据库或数据契约 | 与静态资源拆分无关 |

## 验收标准

| 编号 | 标准 |
| --- | --- |
| A1 | `npm run build` 不再输出 JavaScript chunk 超过 500 kB 的警告 |
| A2 | 首页入口不再包含 Tiptap 或 ProseMirror 编辑器代码，首次渲染编辑器时才请求对应 chunk |
| A3 | React、路由、i18n、Supabase、图标和编辑器依赖按稳定用途生成可独立缓存的产物 |
| A4 | 现有首页交互和编辑器加载行为不变 |
| A5 | 现有相关自动化测试与生产构建通过 |

# R046 Sidebar 全局“全部笔记”入口需求澄清

日期：2026-08-27

## 需求理解

首页侧边栏只保留一个全局“全部笔记”入口，用于清除任何 Roles、Fields 或 Tags 分类筛选并展示当前工作区全部笔记。该入口不应分别重复出现在三个分类分组中。

Fields 的选中态统一使用全局交互强调蓝色，不再使用当前的红色选中态。Roles、Fields 与 Tags 三个分组都只展示实际分类项。

## UI 形态确认

```text
Sidebar
├─ 全部笔记                 9  ← 全局入口，蓝色选中态
├─ Roles
│  └─ Human                 9
├─ Fields
│  └─ inbox                 7  ← 选中时使用蓝色
└─ Tags
   ├─ cuda                  2
   ├─ golang                1
   ├─ tag                   0
   └─ zembra                1
```

## 已确认决策

| 问题 | 决策 |
| --- | --- |
| “全部笔记”数量 | 显示当前工作区的全部笔记数 |
| “全部笔记”点击行为 | 清除 Roles、Fields 与 Tags 的分类筛选，展示全部笔记 |
| 分类分组中的“全部”项 | Roles、Fields、Tags 均不保留单独的“全部”项 |
| Fields 选中态 | 与其他筛选项一致，使用语义化交互蓝色 |
| Tags 分组 | 保留实际标签项，不新增“全部”项 |

## 范围确认

### In Scope

| 范围项 | 说明 |
| --- | --- |
| 全局入口 | 在 sidebar 增加唯一的“全部笔记”筛选入口 |
| 筛选重置 | 点击入口后恢复全部笔记集合 |
| 分组精简 | 移除 Roles、Fields、Tags 中重复的“全部”项 |
| 选中态统一 | Fields 选中态改用现有语义化蓝色 token |
| 测试 | 覆盖全局入口的重置行为及 Fields 的选中语义 |

### Out of Scope

| 非范围项 | 原因 |
| --- | --- |
| 笔记数据、后端 API 或 schema | 本需求只调整前端 sidebar 筛选 UI 与状态 |
| 其他 sidebar 分组的结构调整 | 仅处理全局入口及现有三个分类分组 |
| 标签层级筛选规则 | 保持已有行为 |

## 验收标准

| 编号 | 标准 |
| --- | --- |
| A1 | Sidebar 只出现一个“全部笔记”入口，且不位于 Roles、Fields、Tags 三个分组内部 |
| A2 | 点击“全部笔记”后，Roles、Fields、Tags 的已选分类全部清除，笔记列表展示当前工作区全部笔记 |
| A3 | Roles、Fields、Tags 分组不再出现重复的“全部”项 |
| A4 | 选中 Field 时，其高亮和图标使用既有语义化交互蓝色 |
| A5 | 现有角色、字段、标签筛选仍按原有语义工作 |
